## 📌 1. Мәселе, пайдаланушы және күтілетін нәтиже (Problem & Scope)

* **Проблема:** Университеттің деканаттары, СҚКО (ЦОС) және IT-қолдау қызметі күн сайын жүздеген мәтіндік өтініштер қабылдайды. Оларды қолмен оқып, тиісті мамандарға бөлу 1–3 жұмыс күніне дейін созылады. Бұл кезектердің көбеюіне және шұғыл техникалық ақаулардың дер кезінде қаралмауына алып келеді.
* **Мақсатты пайдаланушы:** Университет студенттері, деканат қызметкерлері, IT Helpdesk операторлары, СҚКО менеджерлері және бухгалтерия.
* **Күтілетін нәтиже:** Студенттердің еркін форматтағы мәтіндік сұранысын бірден қабылдап, 0.2 миллисекунд ішінде 4 негізгі санатқа бөлетін, өтініштің басымдығын (High / Medium / Low) және шешу мерзімін (SLA) белгілейтін интерактивті веб-сервис және REST API прототипі.

### Жіктелетін 4 бағыт (Categories):
1. 🎓 **`academic` (Академиялық мәселелер):** Бағалар, LMS-тегі журнал, силлабус, емтихан кестесі, топ ауыстыру, retake. (Жауапты: *Деканат / Эдвайзер*)
2. 📄 **`docs` (Құжаттар мен анықтамалар):** Оқу орнынан анықтама (Egov), 26-нысан (әскерге), транскрипт, диплом дубликаты. (Жауапты: *Студенттерге қызмет көрсету орталығы - СҚКО/ЦОС*)
3. 💳 **`finance` (Қаржы және төлемдер):** Оқу ақысы, Kaspi арқылы төлеу, бөліп төлеу кестесі (рассрочка), шәкіртақы, жеңілдіктер. (Жауапты: *Бухгалтерия және финотдел*)
4. 💻 **`tech_support` (Техникалық қолдау):** Корпоративтік пошта құпия сөзі, LMS сервер қателері (500/404), кампус Wi-Fi, турникет пропуск карталары. (Жауапты: *IT Helpdesk L1*)

## 📊 2. Деректер және Қауіпсіздік (Dataset & Ethics)

* **Дереккөз:** Синтетикалық және ашық негізде жинақталған 293 шынайы студенттік өтініш (`data/dataset.csv`).
* **Тілдік үлестірім:**
  * Қазақ тілі (`kk`): 133 үлгі (45.4%)
  * Орыс тілі (`ru`): 132 үлгі (45.1%)
  * Ағылшын тілі (`en`): 28 үлгі (9.5%)
* **Санаттар теңгерімі:**
  * `academic`: 74 өтініш
  * `docs`: 73 өтініш
  * `finance`: 73 өтініш
  * `tech_support`: 73 өтініш
* **Қауіпсіздік және этика:** Датасетте нақты студенттердің жеке құпия деректері (ЖСН, телефон нөмірлері, жеке парольдер) жоқ. Жоба деректердің құпиялылығы саясатына толық сәйкес келеді.

## 🧠 3. ML Әдісі және Прототип Архитектурасы

1. **Векторлық кеңістік (TF-IDF Feature Union):**
   * Қазақ тілінің жалғаулық морфологиясын және орыс/ағылшын тілдерінің ерекшеліктерін ескеру үшін екі деңгейлі `FeatureUnion` қолданылды:
     * **Word n-grams:** (1, 2) аралығындағы сөздік тіркестер (мағыналық кілт сөздер).
     * **Char_wb n-grams:** (3, 5) аралығындағы сөз ішіндегі әріптік тіркестер (түбір мен қосымшаларды дәл айыру үшін).
     * Сұраныстардағы диалогтық бос сөздер (`здравствуйте`, `сәлеметсіз бе`, `подскажите`, т.б.) тазартылды.
2. **Модельдер бенчмаркі (80/20 Stratified Split):**

| Модель (Algorithm) | Test Accuracy | Macro F1-Score | Weighted F1 | Latency per query |
|---|---|---|---|---|
| **Logistic Regression (Базалық)** | **84.75%** | **0.8463** | **0.8482** | **0.21 ms** |
| Multinomial Naive Bayes | 83.05% | 0.8288 | 0.8304 | 0.21 ms |
| Linear SVM (LinearSVC) | 84.75% | 0.8436 | 0.8450 | 0.21 ms |

> **Logistic Regression таңдау себебі:** Сызықтық регрессия жоғары F1-көрсеткішімен қоса, әр санат бойынша сенімді калибрленген ықтималдықты (`predict_proba`) береді. Бұл веб-интерфейсте әр бөлімнің үлесін диаграмма түрінде көрсетуге және күмәнді тикеттерді модерацияға жіберуге мүмкіндік береді.

3. **Басымдықты (Priority) есептеу ережесі:**
   * **High (Жоғары):** Сессиялық емтихандар, дедлайн, жүйе қатуы (error 500), кіру бұғатталуы.
   * **Medium (Орташа):** Баға анықтау, оқу ақысын аудару, шәкіртақы, апелляция.
   * **Low (Төмен):** Стандартты анықтамалар, жұмыс кестесі, характеристика.

## ✅ 4. Тексеру нәтижелері (3 Тест-кейс және Қате жағдайы)

### А) Міндетті 3 Тексеру Мысалы:
1. **1-мысал (Оқу мәселесі):**
   * *Мәтін:* «Не отображается оценка за лабораторную работу в LMS»
   * *Болжам:* `academic` (49.5%) | Басымдық: Орташа | Бағыты: *Деканат / Эдвайзер* — **[PASSED]**
2. **2-мысал (Техникалық қате):**
   * *Мәтін:* «Система тестирования зависла во время прохождения экзамена»
   * *Болжам:* `tech_support` (52.8%) | Басымдық: Жоғары | Бағыты: *IT Helpdesk L1* — **[PASSED]**
3. **3-мысал (Анықтама алу):**
   * *Мәтін:* «Где я могу получить справку с места учебы для Egov?»
   * *Болжам:* `docs` (73.0%) | Басымдық: Орташа | Бағыты: *СҚКО (ЦОС)* — **[PASSED]**

### Б) 4x4 Қателер матрицасы (Confusion Matrix):

| True \ Predicted | Academic | Docs | Finance | Tech Support |
|---|---|---|---|---|
| **Academic** | **13** | 1 | 0 | 1 |
| **Docs** | 0 | **14** | 1 | 0 |
| **Finance** | 0 | 0 | **13** | 2 |
| **Tech Support** | 1 | 2 | 1 | **10** |

### В) Қате жағдайды талдау (Error Case Analysis):
* **Сұраныс мәтіні:** *«Не могу оплатить повторный курс из-за ошибки на сайте»*
* **Модель болжамы:** `finance` (35.1%) [Ал `tech_support` — 24.7%]
* **Себебі:** Сөйлемде қаржылық лексемалар («оплатить», «повторный курс») және IT-лексемалар («ошибки на сайте», «не могу») қатар кездеседі. TF-IDF жиілігі бойынша «оплатить» сөзі басым түсіп, өтініш қаржыға кеткен.
* **Шешу жолы:** Күрделі өтініштер үшін тикетті әрі IT-ге, әрі Бухгалтерияға қатар жолдайтын *Multi-label* классификация немесе қателік маркерлерін алдын-ала тексеру (Regex Pre-filter).

### Г) Жүйелік шектеулер (Limitations):
1. **Сленг пен опечаткалар:** Модель сөздікке енбеген бейресми жастар жаргонын («препод», «скиньте лабу») өңдеуде қателесуі мүмкін.
2. **Контекстсіз қысқа сөздер:** «Бағам жоқ», «Қашан?» секілді 1-2 сөзден тұратын өтініштерде ақпарат тым аз.

Жоба ешқандай ақылы қызметке немесе GPU-ға тәуелді емес (CPU-да лезде орындалады).

```bash

uv venv .venv

python test_app.py

python app.py
```
Браузерді ашып, **http://localhost:5000** мекенжайына өтіңіз.

Жоба толықтай бұлттық платформаларға (Render, Railway, Hugging Face Spaces) 1-кликпен жариялауға дайын етіп жасалған (`Procfile`, `render.yaml`, `Dockerfile` қосылған).

   ```bash

   git commit -m "Update student-support project"
   git push origin main
   ```

   `https://student-support.onrender.com`

## SQLite, cookies и дообучение по оценкам студентов

- Обращения сохраняются в `data/student_support.db`; история привязана к подписанному cookie браузера. Входа по имени студента нет, поэтому очистка cookies создаст новую историю.
- Текст хранится для истории. Перед вводом не указывайте пароль, ИИН, телефон или другие личные данные. Кнопка **«Очистить»** удаляет историю и связанные оценки из базы.
- Флажок согласия на форме выключен по умолчанию. Для обучения используются только обращения, для которых студент включил согласие и затем подтвердил либо исправил категорию. Обычные предсказания модели не считаются правильными метками.
- После оценки согласованного обращения приложение автоматически собирает и переобучает кандидата. Требуются минимум две оценки для каждой категории. Скрипт маскирует распространённые форматы email, телефона, ИИН и пароля, сравнивает кандидата с базовой моделью на фиксированной отложенной выборке и заменяет рабочую модель только при отсутствии ухудшения.
- Счётчик на странице включает базовые 293 примера и оценённые согласованные обращения. После обновления приложение сразу загружает новую модель; отчёт появляется в `models/retraining_report.json`. Для ручного запуска доступна команда `python retrain_from_feedback.py`. Очистка базы не удаляет влияние примеров из уже обученной модели.
- Для развёртывания задайте случайный `SECRET_KEY`; за HTTPS также включите `COOKIE_SECURE=1`. Локально ключ создаётся в `data/.app_secret_key` и исключён из Git.
